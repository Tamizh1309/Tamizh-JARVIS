# Tamizh JARVIS Security Model

## Threat Model & Principles

1. **No Raw Shell Access**: LLMs make mistakes and can be susceptible to prompt injection. Tamizh JARVIS strictly refuses arbitrary OS commands or raw shell execution generated by the model.
2. **Four-Tier Risk Classification**:
   - **LOW**: Read-only actions (read tasks, check schedule, query memory, compute advice). Executed automatically.
   - **MEDIUM**: Benign state changes (create a study task, log quiz score, save note). Executed automatically and logged.
   - **HIGH**: Sensitive mutations (delete tasks, update security preferences, run pre-approved system commands, download external resources). **Requires explicit user confirmation**.
   - **CRITICAL**: Irreversible operations (database reset, bulk file deletion, sensitive credential changes). **Blocked by default or requires two-step confirmation**.
3. **Secret Hygiene**:
   - All API keys reside strictly on the backend via environment variables.
   - Frontend never sees provider API keys.
4. **Input Sanitization**:
   - All tool arguments are strongly typed with Pydantic.
   - Unrecognized parameters are rejected.
